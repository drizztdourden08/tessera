The usage files of app parts follow the same rules as Tessera's own. `tessera check` (`brock tessera check`) runs the Tessera usage checks on every part in the `parts` folders of `tessera.config.json`, the views of each `apps` entry included: complete fields, no sentence left from `tessera new`, alternatives that name a Tessera export or an app part, a tree path on the Tessera tree or the app tree, examples that type-check against the app and a `propsHash` that matches the props. `ai.usage` decides: `report` lists and passes, `enforce` fails. `tessera ai` also writes the app guide to `ai.out`, linked to the Tessera guide. `ai.tree` names a module whose `APP_TREE` adds app branches to the decision tree, and `ai.tsconfig` the tsconfig the check reads the parts with. `ComponentUsage` takes the app names and answers an app adds to `TesseraApps` by declaration merging, and `AppTree` types the tree module. The standards extension runs the same checks: notes in report mode, findings in enforce mode. The package now ships `scripts/ai`, and `typescript` is an optional peer dependency the check uses. See MIGRATION.md section 53.
